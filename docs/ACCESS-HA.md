# 进服权限（白名单）高可用优化方案

> **架构定稿（2026-09-09，v2）**：应用户要求，裁决关系为
> 「**在线裁决为主（/access/check），本地快照只做兜底**」——
> 在线检查成功时以在线结果为准（含踢人）；仅当在线层不可用
> （HTTP 失败/超时/格式异常/配置缺失/熔断开启）时，才降级用本地快照裁决。
> 熔断器保留（连续 N 次失败即 OPEN，冷却后 HALF_OPEN 探测），
> 保证后端宕机时玩家不会因为等超时而卡连接。
>
> **实施状态**：本方案（v2）与 H6（封禁本地兜底落盘）、etag 增量、
> 退避重试、`sm_lumi_access_status` 自检命令均已落地并编译通过。
> S4（面板事件推送）需后端配合，暂未实施。

> 目标：LumiAdmin 面板/后端故障时，游戏服**单机自治运行**，玩家可正常进出；
> 后端恢复后自动回到面板管理，全程无人工介入。
>
> 核心思路：把现有「在线裁决为主、快照兜底」**反转**为
> 「**本地快照是常态裁决者，在线接口只做同步与复核**」。

| # | 问题 | 现状代码 |
|---|------|----------|
| P1 | 在线裁决无条件信任，后端白名单事故会连续踢人 | `server/access.sp:101-118` |
| P2 | 快照过期即硬失效，`fail_open=0` 时全体被踢 | `access.sp:178-193` |

| P6 | 降级/恢复/快照过期无醒目日志，管理员无法感知 | 全局 |

## 2. 目标架构（v2：在线为主，本地兜底）

```
玩家连接
   │
   ▼
┌─────────────────────────────────────────────────────┐
│ 在线裁决层（主）                                       │
│  POST /access/check（5s 超时）                        │
│  ▸ allowed=true  → 放行                               │
│  ▸ allowed=false → 踢出（在线结果就是最终结论）           │
│  ▸ 熔断开启 → 完全跳过本层，直接本地兜底                  │
└─────────────────────────────────────────────────────┘
   │ 在线层不可用（HTTP 失败/超时/格式异常/配置缺失）
   ▼
┌─────────────────────────────────────────────────────┐
│ 本地快照兜底层（SQLite: bans + whitelist + rules）     │
│  ▸ 封禁 → 踢（封禁永远优先）                            │
│  ▸ 白名单/门槛 → 不满足按 fail_open 口径处理             │
│  ▸ 快照「陈旧但可用」，过期只告警                        │
│  ▸ 快照完全缺失 → 按 fail_open 放行 + 立即刷新            │
└─────────────────────────────────────────────────────┘
   ▲
   │ 后台定时 + 事件驱动刷新
┌─────────────────────────────────────────────────────┐
│ 快照同步层                                            │
│  ▸ 300s 轮询 /access/snapshot（带 etag 增量）          │
│  ▸ 失败自动退避重试（30s→300s），不影响在线裁决            │
│  ▸ 本地封禁兜底写入 bans 表（H6，幂等去重）               │
└─────────────────────────────────────────────────────┘
```

要点：
- **在线结果就是最终结论**：`allowed=false` 无条件踢（与原始行为一致），
  白名单等在线变更即时生效，不存在「冲突口径」问题。
- **本地快照只在在线层失效时兜底**：断网/后端宕机/超时的情况下，服务器仍按
  最后一份已知快照独立运行，玩家可正常进出（单机自治目标不变）。
- **熔断器的作用从「防误杀」变为「防超时堆积」**：后端宕机时若不熔断，
  每个连接都要等 5s 超时才能降级；OPEN 后直接走本地兜底，连接零等待。
  注意语义差异：熔断期间在线检查被跳过，后端恢复后自动探测回切。

## 3. 详细设计

### 3.1 本地兜底层（在线层失效时执行）

在线检查失败（HTTP 错误/超时/格式异常/配置缺失）或熔断 OPEN 时，立即用本地快照裁决：

```
LocalAccessFallback(steamId, ip):
  1. FindOfflineBan(steamId, ip)            → 踢（封禁优先级最高）
  2. server_rules:
     whitelist_mode_enabled
       → OfflineWhitelistContains(steamId)  → 不在则按 fail_open 口径处理
     access_restriction_enabled
       → OfflineProfileMeetsRequirement     → 不满足按 fail_open 口径处理
  3. 快照完全缺失/损坏 → 按 fail_open 放行并触发立即刷新
```

判定口径：
- **快照存在且结构完整 → 兜底裁决有效**，无论快照新旧（封禁数据宁可「陈旧但可用」）。
- 快照**完全缺失/损坏**（首次部署、DB 打不开）→ 按 `fail_open` 放行并告警，
  同时触发一次立即刷新。
- 快照陈旧不拒绝任何玩家：过期只产生告警日志，绝不作为踢人依据。

### 3.2 在线裁决层 + 熔断器

在线检查是主裁决，`allowed=false` 直接踢出。熔断器只针对「在线层不健康」：

| 状态 | 含义 | 行为 |
|------|------|------|
| `CLOSED` | 正常 | 在线裁决生效 |
| `OPEN` | 熔断中 | 跳过在线检查，连接直接走本地兜底（零等待） |
| `HALF_OPEN` | 试探 | 放行单个在线检查请求，成功→CLOSED，失败→OPEN |

熔断触发条件：连续 N 次（默认 3）在线检查 HTTP 失败/格式异常。
熔断恢复：OPEN 持续 120 秒 → HALF_OPEN 放一个探测请求 → 成功即 CLOSED，
失败回到 OPEN。恢复/触发全程打醒目日志。

> 设计说明（v2）：原方案的滑动窗口拒绝率/冲突率指标已移除——在线为主架构下
> 不存在「本地-在线冲突」概念，`allowed=false` 就是合法踢人，不会误杀；
> 连续失败计数足以覆盖「后端宕机」这一保护目标。

### 3.3 快照同步层（解决 P2/P3）

1. **etag 增量轮询**：`/access/snapshot` 请求带现有快照 `version`，后端无变化
   返回 304/`unchanged=true`，跳过解析与写库；有变化走全量（协议兼容，etag 缺省则全量）。
2. **事件驱动刷新**（需要 LumiAdmin 端配合，可后做）：
   白名单/规则变更时面板向各服推送刷新，插件侧提供 `sm_lumi_snapshot_refresh`
   管理命令 + 服务器命令 `lumiadmin_refresh_snapshot` 作为推送接收端。
   未改造后端时该命令也可手动应急。
3. **原子写库**：快照写入改为「新库文件写好 → 原子 rename 替换」，失败保留旧库，
   永不出现「清空后写入失败」的中间态（现有 `SaveAccessSnapshot` 的
   BEGIN/DELETE/ROLLBACK 在进程崩溃时不安全）。
4. **失败退避**：刷新失败按 30s→60s→120s→300s 退避重试，成功后回到常规间隔。
   刷新失败**绝不**影响本地裁决。
5. **立即刷新触发点**：插件加载、发现快照缺失/损坏、熔断器触发时。

### 3.4 收紧旁路

| 旁路 | 处理 |
|------|------|
| token 未配置，`ResolvePluginApiConfig` 失败 | 直接走本地快照兜底（在线层整体跳过）；告警限流（每 10 分钟一条） |
| 在线响应 `data==null` / 缺 `result` | 视为在线检查失败 → 计入熔断连续失败计数 → 本地兜底（不再静默放行） |
| 拿不到 SteamID64（在线层） | 走本地兜底，由兜底层按白名单模式/fail_open 口径裁决 |

### 3.5 超时与体验

- 在线检查独立超时 `server_access_check_timeout`（默认 5s，独立于通用 10s）；
- 正常路径（在线可达）玩家体验与原始行为一致：在线结果即时生效；
- 后端不可达时最坏等 5s 超时后走本地兜底；熔断 OPEN 后新连接零等待。

### 3.6 可观测性

统一前缀 `[LumiAdmin-Access]`，关键事件全部落日志：
- 降级进入/退出（含原因：快照缺失/熔断/配置缺失）；
- 熔断 OPEN / HALF_OPEN / CLOSED 状态迁移；
- 快照刷新成功（含版本号）/失败（含退避计划）；
- 兜底放行/踢出事件（`sm_lumi_access_status` 可查最近 10 条）。

## 4. ConVar 变更汇总

| ConVar | 默认值 | 说明 |
|--------|--------|------|
| `server_access_fail_open` | `1` | 本地兜底层中「规则无法确认/快照完全不可用」时是否放行 |
| `server_access_snapshot_interval` | `300` | 不变，配合 etag 增量 |
| `server_access_breaker_enabled` | `1` | 熔断器总开关 |
| `server_access_breaker_consecutive_failures` | `3` | 连续 HTTP 失败触发熔断 |
| `server_access_breaker_cooldown` | `120` | OPEN→HALF_OPEN 等待秒数 |
| `server_access_check_timeout` | `5` | 在线检查超时秒数 |

命令：`sm_lumi_access_status`（ADMFLAG_GENERIC）— 输出快照年龄、版本、
熔断状态、最近 10 条事件，运维一键自检。

## 6. 边界与取舍说明

- **在线 vs 可用性**：在线可达时以在线为准（白名单即时生效）；在线不可达时
  依赖本地快照，快照完全缺失且 `fail_open=1` 时放行——这是设计内权衡
  （放行个别封禁者 << 连接全部卡死在超时上）。
- **熔断期间的实时性**：OPEN 状态下白名单变更不再即时生效（跳过在线层），
  后端恢复后 120s 内自动探测回切；紧急情况可用 `lumiadmin_refresh_snapshot`
  手动刷新快照，或临时调小 `server_access_breaker_cooldown`。
- **多物理机共享快照**：`core` 是物理机级共享配置，快照库是每游戏服实例独立
  文件（按现有 `SQLite_UseDatabase` 单库设计），互不影响。
- **回滚**：关闭 `server_access_breaker_enabled` + 把 `server_access_check_timeout`
  调回 10s 即接近旧行为（仍保留本地兜底，比旧版更安全），单服可灰度。

## 7. 免配置自识别（core.smx）与可用性的关系

自 V1.1 起，`core.smx` 支持「只填面板地址，插件自动识别本服」：

- 插件启动后调用 `POST /api/plugin/identify`（`port` + `hostname` + `install_id`），
  面板按来源 IP + 端口匹配服务器并下发该服 `report_token`；
- token 缓存到 `core_identity.cfg`，重启后立即可用；
- 面板重置 token 后按 `core_identify_interval` 自动跟进，或执行 `lumiadmin_reidentify`。

**对可用性的影响：**

| 场景 | 行为 |
|------|------|
| 识别成功 | 与旧版在线裁决完全一致 |
| 识别失败 / 后端宕机 | 无 token → `LocalAccessFallback`，按本地快照裁决（fail_open 默认放行），**玩家不会被卡住** |
| 面板重置 token | 旧 token 暂时失效 → 在线检查走兜底，识别成功后自动恢复 |
| 显式 `core_server` 配置 | 优先级最高，永不参与自动识别 |

也就是说，自识别把「逐服复制 token」这一最容易配错、最影响进服的环节自动化了，
同时沿用了本文档的在线为主 + 本地兜底架构：**token 缺失只会降级，不会阻断玩家**。
